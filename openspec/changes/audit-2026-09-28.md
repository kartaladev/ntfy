# The 2026-09-28 audit: where each finding lives

On 2026-09-28 an adversarial audit examined the whole library, in four areas:
- the core (service, hub, stores);
- HTTP, SSE and WebSocket security;
- email dispatch;
- the adapters (sqlstore, redis, nats, ntfytest).

A fifth pass checked the repository against its own rules and skills.

Every finding was proved by a test that failed against the code of that day, or labelled unverified (`.claude/rules/prove-errors-with-tests.md`).

This file maps each finding to the change that holds it. Each change is ready for `/opsx:apply`:
- its proposal cites the proof and the failing output, re-run on `main` at `20967b3`;
- its `plans.md` opens with that proof as the red step.

Delete this file when the last of these changes is archived.

## Already fixed

In PR #11, `compare-mysql-identifiers-by-bytes` (archived):
- MySQL compared identifiers by collation weight, so one recipient read another's notifications.
- The store conformance suite accepted a store that folds case.
- Identifiers holding NUL or invalid UTF-8 were accepted, and PostgreSQL refused them.
- `MemoryStore.Close` was not atomic when a successor's identifier could not be minted.
- The ID generator's identifiers were unbounded.

## Open, by change

| Change | Findings it carries | Severity |
| --- | --- | --- |
| `make-close-retries-idempotent` | A retried close of every kind, or one naming the successor's kind, closes the successors its first attempt created, on every store. The retention godoc measures close records from the wrong event. | Medium, Low |
| `align-memory-store-with-sql` | Memory replaces a notification under a reused ID. On MySQL, `ON DUPLICATE KEY UPDATE` reports a reused-ID insert as created without storing it. An insert that creates nothing writes a close record on SQL only. The age and close-record cutoffs are compared at nanosecond precision in memory. The email store's empty owner, zero limit and zero purge differ between stores. | Low (MySQL: Medium) |
| `hold-email-delivery-to-its-limits` | An in-doubt resend ignores the attempt limit. A lookup failure on an in-doubt send is never counted. Partial lease loss abandons an unsent email. On PostgreSQL, one dispatcher's overlapping passes email twice. A pass sends after its context is cancelled. | Medium, Low–Medium |
| `end-broadcaster-listen-with-its-connection` | NATS `Listen` never returns once its connection closes. The Redis cancel test races the server's unsubscribe, which is what made `make all` fail intermittently. The broadcaster suite accepts three broken broadcasters. | Medium, Low, Low–Medium |
| `serialise-sqlite-writes` | On SQLite, `MarkRead` and `ClaimEmails` fail under concurrency unless the host sets `_txlock=immediate`. | Medium (SQLite hosts) |
| `refuse-wiring-mistakes-at-construction` | These are accepted at construction and fail later: a table prefix over 31 bytes (the documented 29 is wrong too), a base path without a leading slash (`/a{` panics), malformed or contradictory origin patterns, and a reconnect delay that overflows. Nil options are handled inconsistently. | Low |
| `harden-http-read-state-and-stream-caps` | The mark-read routes accept cross-site form posts. Stream caps count the followed recipient, not the acting user. | Low–Medium, Low |
| `bind-cursors-to-exact-filters` | Cursor fingerprints collide across kind filters (`["a","b"]` against `["a,b"]`, and no filter against `[""]`). | Low |
| `conform-to-project-rules` | Non-conformance with the repository's own rules: the CI toolchain pin, `go.mod` tidiness, hand-written doubles, tables without `assert` or `ctx`, godoc gaps, missing linters, goleak in sqlstore, examples, LICENSE, fuzz tests. | Process |

Reviewed and left as they are, with reasons in the relevant proposal or design:
- a subscription policy's error answered `403` even when transient;
- the WebSocket origin check comparing hosts only (unverified);
- a close interleaving with a different close's retry on one subject (needs a schema change);
- the SQL stores possibly leaving a send in doubt when its context ends mid-send (unverified).

## Shared requirements: apply in this order

These changes were written in parallel from the same `main`. Pairs of them rewrite the same spec requirement:

| Capability :: requirement | Changes |
| --- | --- |
| `notification-email` :: Concurrent dispatchers never send the same notification twice | `hold-email-delivery-to-its-limits`, `serialise-sqlite-writes` |
| `notification-inbox` :: Every store behaves identically | `align-memory-store-with-sql`, `serialise-sqlite-writes` |
| `notification-realtime` :: Streams stay alive, and slow clients never slow publishers | `harden-http-read-state-and-stream-caps`, `refuse-wiring-mistakes-at-construction` |
| `notification-retention` :: Close records outlive late redelivery, then expire | `align-memory-store-with-sql`, `make-close-retries-idempotent` |

A `MODIFIED` delta replaces the whole requirement when it is archived. So of each pair, **the second to be archived must first rebase its delta on the synced spec**: `/opsx:update` the change, keeping the first change's scenarios. The same applies to code both changes edit, such as `memory.go` and `sqlstore/insert.go`, and `hub.go` and `http.go`.

Suggested order. Correctness comes first, and each change's shared requirements are rebased as they land:
1. `make-close-retries-idempotent`
2. `align-memory-store-with-sql`: rebase `notification-retention` onto 1.
3. `serialise-sqlite-writes`: rebase `notification-inbox` onto 2.
4. `hold-email-delivery-to-its-limits`: rebase `notification-email` onto 3.
5. `end-broadcaster-listen-with-its-connection`
6. `refuse-wiring-mistakes-at-construction`
7. `harden-http-read-state-and-stream-caps`: rebase `notification-realtime` onto 6.
8. `bind-cursors-to-exact-filters`
9. `conform-to-project-rules`: last, because it touches tests across every package.

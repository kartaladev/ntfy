# Email Delivery Robustness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the email dispatcher's at-least-once contract describe what it actually does, keep every retry in the future, stop the host's data reaching the delivery record, and close two construction-time gaps.

**Architecture:** Four independent defects in one file, `email_dispatcher.go`. One is a documentation-and-spec correction with no code change (the at-least-once wording); one is arithmetic (`delay` overflows); one is a guard (`validate` dereferences an unset pointer); one is a policy change (a recorded reason becomes a library-owned classification, with an opt-in host rule). Each is proved by a test that fails first, fixed, then pinned in the shared conformance suite where a host store could diverge.

**Tech Stack:** Go 1.26, standard library only in the core module. Tests use `stretchr/testify` (`assert` and `require`), `go.uber.org/goleak` via `TestMain`, and the project's own conformance suites in `ntfy/ntfytest`. `uber-go/mock` generates `email_mock_test.go` from `email.go`.

**Spec:** `openspec/changes/email-delivery-robustness/` — read `proposal.md` (why), `design.md` (D1–D5, the decisions this plan implements), `specs/notification-email/spec.md` (the requirements and scenarios), and `tasks.md` (the task list this plan expands).

## Global Constraints

- **Go toolchain is pinned:** every `go` command in this plan runs under `GOTOOLCHAIN=go1.26.8`. Either export it once (`export GOTOOLCHAIN=go1.26.8`), rely on the repository's `.envrc` with direnv, or go through `make`, which exports it itself. Go 1.27 on `PATH` will otherwise be used and the repo's `golangci-lint` binary will crash.
- **The core module imports nothing but the standard library.** `.golangci.yml`'s depguard allow-list and `make split-check` both enforce it; testify, goleak and mock are test-only dependencies already present.
- **Table-driven tests follow the project's `table-test` skill**, not the generic Go one: a `cases := []testCase{...}` slice where each case carries an `assert func(t *testing.T, ...)` closure — never `want`/`wantErr` fields — and `t.Context()` rather than `context.Background()`. Every existing test in `email_test.go` and `email_dispatch_test.go` is already in this shape; copy it.
- **Test doubles come from the `use-mockgen` skill.** `email_mock_test.go` is generated by `//go:generate mockgen -source=email.go -package=ntfy -destination=email_mock_test.go -typed` (`email.go:3`). This plan adds a struct and a func-typed option to `email.go`, not an interface, so regeneration is not required; if you add an interface there, run `go generate ./...` and commit the regenerated file.
- **Heavy stores come from the `use-testcontainers` skill** through `make store-matrix`; never hand-roll a database fake.
- **`make all` (lint, split-check, test) and `make store-matrix` must pass** before the change is done.
- **Every claimed defect is proved by a failing test first** (`.claude/rules/prove-errors-with-tests.md`): write the test, run it, see it fail *for its own reason*, and only then fix. Anything that cannot be reproduced here is labelled **Unverified** and pins only the library's own behaviour.
- **Every behaviour decision states a default and its override** (`.claude/rules/library-design.md`), or explains why it has none. Two decisions here have no override on purpose: the at-least-once guarantee boundary (D1) and the retry-delay bound (D2).
- **Commit messages are imperative sentence case with no prefix** (`Bound the retry delay`, not `fix: bound retry delay`) and carry no attribution lines.
- **Line length and formatting** are enforced by `gofumpt` and `goimports` with local prefixes `github.com/kartaladev/ntfy` and `github.com/kartaladev/sqlkit`; run `make fmt` if a hand-written block drifts.

// upperBound is the most a delay may be: the ceiling plus the jitter, or the
// largest duration when the ceiling is close enough to it that adding the
// jitter would overflow.
func upperBound(ceiling time.Duration) time.Duration {
	if ceiling > math.MaxInt64-ceiling/5 {
		return math.MaxInt64
	}

	return ceiling + ceiling/5
}

			assert.Positive(t, delay, "a retry is always scheduled into the future")

- [ ] **Step 3: Bound the doubling and the jitter**

In `email_dispatcher.go`, replace `delay` (`:566-580`) with:

```go
// delay is how long to wait after an attempt: the backoff doubled for each
// earlier attempt, capped at the ceiling, with jitter. The doubling stops
// before it can overflow, so a delay is always positive however large the
// ceiling and however many attempts have been made.
func (d *EmailDispatcher) delay(attempts int) time.Duration {
	wait := d.backoff

	for i := 1; i < attempts; i++ {
		if wait >= d.ceiling/2 {
			wait = d.ceiling

			break
		}

		wait *= 2
	}

	return jittered(min(wait, d.ceiling))
}

// jittered spreads a delay by up to emailJitter either way, without overflowing
// and without reaching zero, so that deliveries failing together do not retry
// in lockstep and no retry is scheduled in the past.
func jittered(wait time.Duration) time.Duration {
	spread := time.Duration(float64(wait) * emailJitter * (2*rand.Float64() - 1))

	if spread > 0 && wait > math.MaxInt64-spread {
		return math.MaxInt64
	}

	return max(wait+spread, time.Nanosecond)
}
```

Add `"math"` to the import block (`:3-9`), keeping the standard-library group's alphabetical order: `context`, `errors`, `fmt`, `math`, `math/rand/v2`, `time`.

The inner conversion cannot overflow: `float64(wait) * emailJitter` is at most `float64(math.MaxInt64) * 0.2`, well inside `int64`. The old code multiplied by `spread` of up to 1.2 *after* clamping to the ceiling, which is exactly how a ceiling near `math.MaxInt64` produced an out-of-range conversion.

// can assert what reached the delivery record on any store alike.
type recordingEmailStore struct {
	ntfy.Store
	ntfy.EmailStore

	mu      sync.Mutex
	records []ntfy.EmailRecord
}

func (s *recordingEmailStore) RecordEmails(ctx context.Context, record ntfy.EmailRecord) (int64, error) {
	if err := ctx.Err(); err != nil {
		return 0, err
	}

	s.mu.Lock()
	s.records = append(s.records, record)
	s.mu.Unlock()

	return s.EmailStore.RecordEmails(ctx, record)
}

// reasonOf returns the reason last recorded for a notification.
func (s *recordingEmailStore) reasonOf(id string) string {
	s.mu.Lock()
	defer s.mu.Unlock()

	for i := len(s.records) - 1; i >= 0; i-- {
		if slices.Contains(s.records[i].IDs, id) {
			return s.records[i].Reason
		}
	}

	return ""
}
